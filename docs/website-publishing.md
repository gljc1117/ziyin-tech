# 官网发文工作台

入口：`https://www.chcomct.cn/publishing/login`。

发文人使用个人邮箱及本人设置的密码。首次邀请邮件返回官网时，原有密码回调页接收邀请；设置密码后点击「前往官网发文登录」。忘记密码使用 `/staff/set-password`，完成后同样进入发文登录。

## 日常操作

1. 登录后点「新建文章」，填写标题、栏目、署名、摘要及正文。
2. 正文可直接粘贴，或导入 UTF-8 `.md` / `.txt`；最大 800 KB、正文最多 20 万字。Word 请复制正文；此版本不上传或解析 Word/PDF 附件。Markdown 支持 HTTPS 配图链接；预览确认配图来源可公开。
3. 点「保存草稿」。草稿不在公开网站或匿名数据库查询中显示。
4. 点「预览文章」核对版式，确认署名、引用、图片和公开授权，再勾选公开确认并点「发布到官网」。文章会出现在「动态与洞察」，学术观点归入「子殷洞察」。
5. 点「查看官网文章」核对正式页面。已发布文章的「保存更新并同步官网」立即更新正文；「撤回为草稿」停止公开。每次操作保留不可由发文人删除的版本快照。
6. 出现版本冲突时先复制未保存正文，再刷新列表；不覆盖另一页面的新版本。
7. 离开工作设备时退出账号。

## 授权边界

`website_publishers` 是独立名单，不使用 `staff_members`。账号必须同时通过 Supabase Auth 服务器验证与当前 active 名单检查。API 使用调用者 JWT 和公开 anon key，不使用 service-role。数据库 RLS 与列权限进一步约束可见行、作者归属及可修改字段。发文人不能修改他人或历史无归属文章、删除文章/版本、修改账号权限，且不会获得合作需求或评论管理权限。

公开 `news` 查询仅允许 `is_published = true`；移除历史不受限读取规则，新增记录默认为草稿。`news_revisions` 快照只对相应有效发文人及受信任的数据库管理员开放。停用名单后，下一次 API 或直接数据库请求停止获得私有草稿、历史及写入权限；已经公开的文章仍可像普通访客一样阅读。

账号开通必须核实具体邮箱和 Auth 用户 ID，通过受信任的管理端邀请，再向独立名单写入该用户 ID。不得仅凭邮箱后缀、前端字段、职位或可由用户修改的 metadata 授权。不要为发文而开通客户业务员工权限。

## 验证与部署

本功能的验证为 `npm run test:publishing`，包括真实隔离 PostgreSQL/PGlite 权限测试及实际 API 处理器与 SDK 的 HTTP 测试。共享认证及文章展示另运行 `test:staff`、`test:comments`、`test:trust`、TypeScript、相关 ESLint 和构建。

先部署已验证的兼容数据库迁移，再发布包含 UI/API 的源代码；迁移不改动现存新闻正文或发布状态。源代码回退时保留数据库收紧后的权限及全部文章/历史记录。不要通过恢复无条件公开读取规则进行回退。

账号本人首次收信、设置密码、登录及真实内容发布须由账号本人验收；管理员不得冒用其账号发布测试文章到公开官网。

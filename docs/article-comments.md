# 文章交流与讨论

## 读者与员工流程

- 在 `/news/[id]` 的“学术观点”“学术动态”文章中，正文及参考文献后显示“交流与讨论”。公司报道、病例页本次不开放。
- 读者无需注册，填写昵称（2–30 字）和评论（5–2000 字）。昵称与正文将公开，不收集邮箱、手机号、IP 或患者资料。
- 保存成功返回 202，页面即时显示“系统提示 · 自动回执”：“您的留言已收到，感谢关注子殷科技！我们将尽快查看并答复。留言审核通过后，将在本文评论区展示，请留意后续回复。”待审核内容不会出现在公开列表。保存失败保留输入，不伪报成功。
- 自动回执仅确认此次提交已收到，不生成或保存官方回复，不发送邮件，也不调用 AI。专业答复仍由员工审核填写。
- 员工从合作需求工作台进入 `/staff/comments`。可按待审核、已公开、已隐藏查看，每页 20 条。
- 选中评论后选择状态、填写可选官方回复并保存。回复统一署名“子殷科技 · 官方回复”。隐藏评论会同时撤下回复；员工不能篡改读者原文。
- 每次读取和保存都验证 Supabase 用户及 `staff_members.active`。沿用现有员工白名单，所有活跃员工均可审核。记录最后审核人、修改时间和版本；不声称拥有完整审核历史。

## 数据库与权限

迁移：`supabase/migrations/20260924053524_article_comments.sql`，由 Supabase CLI 2.117.0 的 `migration new` 创建。依赖已经部署的员工管理迁移。

新增 `public.article_comments`，不修改现有账号、员工成员、文章或合作需求记录。启用 RLS，显式撤销默认权限后按角色授予列权限：

| 身份 | 读 | 写 |
| --- | --- | --- |
| anon | 已公开评论的公开字段 | 仅文章 ID、昵称、正文、提交编号；强制待审核 |
| 普通 authenticated | 无 | 无 |
| 活跃员工 | 全部评论 | 仅可修改可见状态和官方回复 |

公开网站接口另外核对文章存在且分类允许评论；员工发布接口也重新核对。源文件文章与数据库文章有不同 ID 类型，所以评论以受长度/格式约束的文本关联，不设指向单一文章表的外键。直接调用 Data API 可能创建未知文章 ID 的待审核记录，不能自行公开；后台对这类记录提示隐藏。

私有 intake 触发器为了跨 RLS 统计待审记录而使用固定 `search_path` 的 SECURITY DEFINER，无公开执行权限，只校验/计数，不读取返回留言内容、不审核。其余审核触发器为 SECURITY INVOKER，使用现有 `private.staff_role()` 验证实际员工权限。

不需要新增服务端密钥或第三方评论服务，复用现有 `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`。浏览器不接触服务密钥。

## 重试、限流和内容处理

- 同一提交 UUID 重试不会重复插入；客户端在网络失败后保留该编号。
- 数据库串行锁保护限流检查；同文同昵称 1 分钟 1 条，同文同正文 24 小时内去重，全站 30 条/分钟、200 条/小时。
- 上述是基础限流与队列保护，不是身份认证或完善的机器人识别。攻击者更换昵称仍受全站限流影响，亦可能消耗额度。若遭持续滥用，可接入验证码/边缘限流。
- 网站接口另有蜜罐、请求体 12 KiB 限制、来源检查和字段白名单。直接 Data API 仍受数据库限流、字段权限及 RLS 控制。
- 评论与回复按纯文本渲染，不支持 HTML、附件、读者互相回复、点赞或邮件通知。
- 更新使用版本条件，旧页面保存返回 409，避免覆盖同事的修改。
- 公开接口与员工接口均禁止响应缓存，刷新后看到审核结果。

## 验证与发布

执行 `npm run test:comments`：使用隔离 PGlite PostgreSQL 执行真实迁移、真实数据库角色权限，以及实际 TypeScript API 配合隔离 HTTP 服务验证会话、输入、错误与分页。测试不接触正式客户数据。

2026-09-24 已通过评论 16 项测试；包括待审不可读、批准/隐藏/官方回复、匿名及非员工越权、已停用员工、原文不可改、版本冲突、重复提交、限流、无配置和数据库失败等。

发布步骤（候选审核通过后）：

1. 对既有 Supabase 项目应用上述新增迁移，不重新执行旧迁移；运行安全 advisors 并检查新表 RLS、列权限和触发器。
2. 在候选部署确认公开列表可读、员工审核可用。实际测试留言须明确标注测试并保持待审/隐藏，不能制造真实读者评论。
3. 合并候选版本并检查正式文章与后台。必要时先退回上一网站版本；保留评论表和已收留言，不通过删表回滚。

本候选交付时尚未对正式 Supabase 执行迁移，所以远端候选页面可能显示评论服务暂不可用。数据库和 API 功能已经在隔离环境验证；正式数据库 advisors、真实登录后的审核交互和移动设备体验需在启用阶段验收。
